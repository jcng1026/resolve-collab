## Other findings

- `Resolve()` blocks for ~4 s and then fails on Free. The plain `resolve` global works.
- `print()` from menu scripts is not shown or logged. Errors from menu scripts go to `ResolveDebug.txt`.
- `bmd.fileexists` / `bmd.direxists` work for real paths.
- **Packaged-app redirection:** files written under `%LOCALAPPDATA%` by tools started from the Claude desktop app are invisible to Resolve (Windows MSIX file virtualization). The feasibility state now lives in the repo's gitignored `local/` folder. ResolveCollab's own installer must not rely on `%LOCALAPPDATA%` if it runs from a packaged app.
- `SetPrefs` / `GetPrefs` share memory between menu scripts and the Console, but never reach the companion.

## Blocking problem: no inbound channel on Free

Outbound (bridge → companion) works through the error log. **Inbound (companion → bridge) has no documented file-read path on Free 21.1.2**, so the bridge cannot receive remote edits as designed in SPEC §3.2. Candidates, all untested:

1. **Timeline import:** the companion writes a small OTIO/EDL whose marker notes carry the message; the bridge imports it with `ImportTimelineFromFile`, reads the markers, and deletes the timeline. Briefly touches the project.
2. **Preset import:** the companion writes a preset file (burn-in, render, keyboard…) whose *name* carries the message; the bridge imports it, reads the preset list, and deletes it. User-level, not project-level.
3. **Studio-only live sync:** Studio allows external scripting, so the companion could drive Resolve directly with no bridge. Free would not be supported for live sync.
